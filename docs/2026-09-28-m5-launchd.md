# M5 排程观察方案（launchd）

> 本轮（第 1、2 阶段）**不加载、不启用、不修改任何定时任务**，只记录现状与可复核的观察方法。

## 1. 为什么是 launchd 而不是 cron

本机 `cron` 无法写入 `~/Documents`（macOS TCC 拦截；实测写主目录成功、写项目 `logs/` 失败）。因此项目排程必须使用 **launchd**（LaunchAgent）。

## 2. 现状（本机实测）

执行与结果：

- `launchctl list | grep -i contenthub` → 仅 `com.contenthub.schedulertest`（PID `-`，上次退出码 `78`）。
- `ls ~/Library/LaunchAgents/` → 只有 `com.contenthub.schedulertest.plist` 与项目无关的用户级 agent。
- `crontab -l` → 现存条目全部属于 `skills/youtube-clipper`，**没有** content-hub 的 05:00 / 06:00 / 10:00 / worker 条目。

自检 agent 详情（`~/Library/LaunchAgents/com.contenthub.schedulertest.plist`）：

- Label：`com.contenthub.schedulertest`
- 动作：`/bin/date "+%Y-%m-%d %H:%M:%S scheduler-ok (launchd)"`
- `StartInterval`：600 秒；`RunAtLoad`：true
- 输出：`logs/scheduler_test.log`、`logs/scheduler_test.err`

结论：**当前没有任何 content-hub 生产定时任务处于加载状态**。自检 agent 只证明 launchd 能按间隔在该项目目录写日志，不证明生产排程已经运行。生产排程未配置本身是一个 Known Gap。

## 3. 设计基线与实际观察的差别

`README.md` 与脚本描述的次序（`run_all.sh` 采集 → `run_daily_full.sh` 创建公众号文章 → `publish_worker.py` 消费草稿队列 → `run_daily_case.sh` 创建案例）是**设计基线**，不是线上执行证明。只有加载了对应的 LaunchAgent 并观察到连续运行记录，才能宣称排程恢复。

README 的目标执行时点（设计值）：05:00 采集、06:00 创建文章、10:00 案例、worker 每 5 分钟一次。当前均无对应已加载 agent。

## 4. 未来观察字段（连续运行证据）

在获得人工批准并加载排程后，每个时点按下列字段记录；缺少实际记录时不得宣称恢复。

- **05:00 采集（`run_all.sh`）**
  - 运行时间、退出码、`logs/collect_<date>.log` 路径
  - 采集条数 → 可评分数 → 文章候选数（原始路径：`platform/jobs/<date>/.../index.json`）
- **06:00 文章（`run_daily_full.sh` / `platform_cli.py run article-daily`）**
  - 运行 ID（`platform/jobs/<date>/<job>/runs/<run_id>/job.json`）
  - 选中数 → 终稿合格数 → 入队数 → 草稿成功数
  - 状态语义：2 篇 `success` / 1 篇 `partial` / 0 篇 `failed`，附拒绝原因计数
  - 总耗时与阶段原因
- **10:00 案例（`run_daily_case.sh`）**
  - 运行 ID、案例状态、与案例历史的主题去重结果（`cluster_ids`）
  - 是否误用文章窗口
- **worker（`run_publish_worker.sh`，每 5 分钟）**
  - `logs/publish_<date>.log` 的每次通过记录
  - `queue/pending.jsonl`、`processing.jsonl`、`done.jsonl`、`failed.jsonl` 的计数与哈希
  - 是否出现重复入队、同一文章重复草稿
- **跨时点汇总**
  - 连续失败次数与告警是否到达（`platform/state/pipeline_health.json`；外部渠道仍未连接）
  - 重复素材与告警到达情况
  - 每天漏斗（`content_platform/audit/funnel.py`）与基线对比

连续性要求：在 05:00、06:00、10:00 与 worker 的连续运行记录齐全前，保持 M5 为“未完全通过”。

## 5. 人工审稿回退

若终稿门或排程出现意外：

1. 暂停自动入队（停止/卸载对应 LaunchAgent），保留已生成稿件供人工审核。
2. 不关闭质量检查换取表面成功率。
3. 查清状态（run ID、阶段原因、队列哈希）后再恢复。
4. 回退只针对本里程碑改动，不清理历史产物或重置现有工作区。

## 6. 本轮操作边界

- 不创建、不加载、不启用、不修改任何 LaunchAgent。
- 不修改 `~/Library/LaunchAgents/com.contenthub.schedulertest.plist`。
- 不写 crontab。
- 以上现状记录仅来自只读命令。
